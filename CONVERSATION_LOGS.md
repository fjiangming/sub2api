# Upstream conversation capture

The fork dev release adds opt-in raw upstream application-body observation for the companion operations center. It does not change billing, deduct balances, replay inference or write a raw disk spool.

Core environment variables (leave unset to disable):

```dotenv
CONVERSATION_LOGS_URL=http://operations-center:9872
CONVERSATION_LOGS_TOKEN=<separate-random-token-at-least-32-characters>
```

Set the same token in the operations center and ensure private network reachability. Saving starts disabled; configure excluded users and the save policy in its Conversation Logs tab before enabling. These settings are provided for a later approved deployment; no server configuration is changed by a source release.

Capture uses authenticated user/key IDs, actual HTTP RoundTrips and WebSocket lease/relay boundaries. Original body bytes are not reformatted; HTTP transport auto-decompression may already have occurred, while encoded bodies exposed by the transport remain encoded. Headers, URL query strings and TLS/network frames are outside the archive. Downloads reproduce the captured bytes, including numeric spelling and unknown fields.

Policies are checked before capture, before sending and again before database insertion. Excluded users create no new archive body, metadata, session, index or gap record; in-flight archives are discarded after an exclusion. Existing history follows retention. Policy failure disables the attempt's capture without failing inference. Persistent WebSocket connections denied at their first segment need reconnecting to resume capture.

The operations-center save policy can restrict collection to selected upstream models, with an optional Kimi K3-and-later range. Matching ignores case and whitespace, supports Fable/Opus shorthand and Gemini carbon, and otherwise requires an exact named version. Unknown and unselected models produce no new archive body, metadata, session, index or gap. Enabled empty selection means collect none. Existing encrypted policies default to the previous unrestricted model behavior until explicitly configured; clients omitting the new fields preserve an existing selection. Excluded users remain excluded regardless of model.

Models are identified from observed outbound JSON/multipart, Gemini/Vertex model paths and WebSocket top-level/response model fields, with model inheritance within the same authenticated lease. HTTP assembly and model identification happen in the background after observation ends. All candidates must pass the attempt policy and current send policy; ingress checks users/models before decoding. Unknown or disallowed models never reach persistent storage. Historical archives remain readable, but excluded historical models cannot write reprocessing copies.

Inference always takes priority. Request goroutines use an asynchronously refreshed policy cache; they never wait for archive network, disk, masking or acknowledgments. Refresh runs every second with a 200ms deadline; a failed or more-than-three-second-old cache skips capture. Startup warmup can skip requests, and fresh send/ingress checks reject newly excluded users even while the cache was valid.

There is no configurable per-attempt truncation or 10,000-frame cap in capture v2. HTTP observations use 16 KiB chunks; frame bytes and metadata share the existing 64 MiB global memory budget and 32-item completed queue. WebSocket observers only copy and nonblockingly enqueue frames (16,384 pending entries); a separate worker identifies models and segments messages. Policy/WS lock contention, full queues or exhausted budgets abandon the affected archive rather than wait for logging. Failed scopes stop further observation; earlier completed segments can remain. Individual bodies larger than the available global budget cannot be archived. Assembly, model parsing and delivery need additional bounded-worker heap; 64 MiB is not a total process RSS limit.

Normal response Close preserves native cancellation and never waits for archive completion. Already-started Read/WriterTo observations receive up to 250 ms to finish copying their n+error bytes in a separate finalizer. That finalizer performs no additional reads. A stalled observation expires conservatively; bytes returning after sealing cannot change the archive. Pending finalization, ready delivery and retries share 32 total owned slots, rather than multiplying the queue bound. Idle finalization does not poll.

An observed HTTP response can additionally hand off its unread raw tail in the background when an existing OpenAI Responses/chat/messages parser actually finalizes a terminal, the shared Anthropic-to-chat/responses parser closes an in-band error, or native code closes an HTTP error response (status >=400). There is no universal reader pump or inference-path queue. The tail waits for any native Read to finish before taking sole ownership of the raw reader, including below decompression. It preserves compressed bytes, trailing bytes and complete failed responses without extending the business error parser's size limit. New foreground reads after handoff are refused. At most two tails run, each for one second total / 200 ms idle, sharing the 32 jobs and 64 MiB budget, including its 16 KiB scratch buffer. Only an admitted handoff defers header/context cleanup and native inFlight release until physical close; user Close returns immediately and archived business duration excludes the tail.

New attempts on the same cached upstream client immediately yield/cancel optional tails, including when the new request is not collected. Older foreground responses continue normally but cannot start a new tail after that newer attempt; epoch checks also cover out-of-order response headers. This prioritizes small connection pools and busy accounts over archival. Cancelled clients/attempts, incomplete requests, prior read errors, unsupported body wrappers, model/user denials and resource pressure retain native close behavior. After joining a native read, recheck its actual EOF/length/error before parsing or reading again. Zstd is excluded from handoff because its native asynchronous decoder can read outside the repository mutex; its original decoding concurrency, cancellation and observation grace remain intact, with no second raw reader. Existing native cancellation, billing drain, request deadlines, forwarding, usage and failover are not replaced. Native Anthropic/Gemini paths which read through EOF retain their loops; not every protocol/wrapper has an early-terminal handoff. Tail expiry/preemption can still leave a record incomplete. A terminal permits a read; only actual EOF or matching declared body length, together with no observed read error, can establish raw completeness, independently of HTTP/model success. Shared resources and connection-cancellation scheduling still have costs; this is not hard latency isolation.

One background sender hashes chunks and streams base64 into the unchanged JSON contract, without allocating a full encoded envelope. It tries the same event at most three times, with delayed retries of 500 ms / 2 s so another archive can proceed first, and fresh policy gates before every send. Background POSTs retain a two-second timeout unless the center advertises durable_receipt_version=1, allowing five seconds only for that archive request; policy reads remain 200 ms. The receiver and sender verify a SHA-256 digest covering byte lengths, both bodies, and frame order/direction/time/binary flag/body. Successful delivery requires a matching ID/digest acknowledgment. There is no core disk spool, core crash recovery, guaranteed shutdown drain or inference retry. Process exits, exhausted memory/queue, unreachable archives and failed writes can still lose complete records. No observer lock is held during delivery. Pipe cancellation joins the encoder before releasing body ownership.

This is low-overhead best effort observation, not literally zero-cost capture. Synchronous immutable copying, allocation and shared CPU/GC can still affect first-byte and total latency, especially for large requests or bursts. The companion operations center separates raw reception from masking into independent bounded, low-priority processes. It commits encrypted originals and a durable processing reference before acknowledging receipt, then parses completion evidence and masks in the background. Processing can resume after a center restart; a processing crash cannot erase an already committed source. Busy/unavailable reception, memory refusal or crashes before persistence can still lose a whole archive, without a production synchronous fallback. Synthetic benchmarks in `performance_test.go` and the release checks report overhead; they do not guarantee unchanged production P95/P99. See the companion performance review and reliability documentation for measurements and limitations.

Early close and read/transport errors preserve only bytes actually observed and remain explicitly incomplete. Complete means observed byte completion, not model success, terminal SSE semantics, billing success or an entire multi-turn conversation. Retention, model/user exclusions and missing session identifiers can make a session discontinuous. The companion UI separates collection, processing and delivery states; incomplete records cannot be pushed. Legacy collectors remain compatible but still truncate, so update both components for capture v2 and check the displayed collector version.

Optional HTTP transport diagnostics v1 are negotiated through `transport_diagnostics_version: 1` in the existing collector policy. Before the first archive send, a fresh supported policy permits `transport_diagnostics`: observed request/response byte counts, declared lengths (-1 when unknown), EOF observation, a fixed first-error enum and whether Close had begun when that read returned. Raw error messages are never included. Metadata is assembled by the background sender; observation reuses existing counters/locks with atomic close / active-observation state. Diagnostics themselves add no reads, body parsing or synchronous archive I/O. The separately bounded tail is described above. Errors arriving after sealing cannot update the event. Real non-EOF errors remain incomplete even after a terminal event, including bounded archival cancellation; the close phase alone does not identify its cause.

Deploy the companion center first for diagnostics. Old collectors ignore the capability, and a new collector omits optional metadata when the center does not advertise support. Retries preserve the first envelope exactly; a mid-retry capability downgrade abandons the archive rather than changing its fingerprint. No new environment variable is needed. Close phase establishes observation order, not the cause of an error or proof of complete upstream/client delivery. Historical generic read_error cannot be retrospectively attributed or repaired, and WebSocket frames retain their existing observation contract. Companion limited-inspection warnings continue to preserve opaque images/signatures/encrypted contexts; repeating the same redaction rules cannot inspect their internals.

The operations center preserves encrypted source on processing errors (including masked-only mode), offers reprocessing using current rules, and refuses a whole new record when storage is full. Original retained bytes can be downloaded unchanged; previously discarded bytes cannot be recovered. Operator settings, privacy categories and explicit limitations are maintained in the companion documentation.

The existing companion billing-recovery UI may report unavailable against the native core; this archive does not restore those unrelated custom APIs.

Every dev push triggers Fork Dev Release. Tested five-platform archives and checksums are published to this fork's GitHub Releases; native amd64/arm64 images are published to `ghcr.io/fjiangming/sub2api:<numeric-version>`. Only the highest completed numeric release advances GitHub latest and image aliases `dev` / `latest`. The updater and version menu point to this fork. Source publishing never updates a running server.
